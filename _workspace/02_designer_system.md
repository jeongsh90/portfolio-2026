## 0. 디자인 레퍼런스 부재 — 채택한 방향과 근거

**레퍼런스/스크린샷이 제공되지 않았다.** 에이전트 규약(에러 핸들링)에 따라 IA의 톤을 근거로 자체 판단해 방향을 확정하고, 그 근거를 아래에 남긴다. 실제 레퍼런스가 나중에 제공되면 §1 컨셉과 §2 팔레트부터 재조정한다.

| 판단 근거 (IA에서 읽은 사실) | 도출한 디자인 결정 |
|---|---|
| 스크롤로 이어지는 롱폼이 아니라 **페이드로 교체되는 4개의 독립 화면**(IA §1) | 사이트를 "한 장씩 교체되는 **낱장(sheet)**"으로 은유. 페이드 전환이 장식이 아니라 구조의 필연이 되게 함 |
| 직군 미확정(A1), 콘텐츠 전부 플레이스홀더 | 콘텐츠가 아니라 **조판(組版) 자체가 인상을 책임져야 함** → 타이포·괘선·여백 중심. 일러스트/그라디언트/글래스 같은 장식 의존 금지 |
| V0은 "메뉴가 곧 화면"(IA §3 디자이너 참고) | 3개 진입 메뉴를 **화면 우측 전체를 세로 3분할하는 거대 행**으로. 가운데 정렬 히어로 + 하단 작은 버튼 구조 폐기 |
| 세 뷰를 같은 카드 그리드로 처리 금지(IA §10) | V1=행(row) 대장, V2=좌측 고정 세로축, V3=산문 단일 컬럼+좌측 이탈. **셋 다 카드 박스가 존재하지 않음** |
| 모든 스크롤 영역에 GSAP 스무스 스크롤 | 각 뷰가 **정확히 하나의 스크롤 컨테이너**만 갖도록 셸을 고정 행(내비/헤더)과 스크롤 행으로 분리(§7) |
| 한국어 단일, 영문 병기 슬롯 1개(A6) | Pretendard 본체 + **숫자/영문 전용 세리프**의 2중 활자 대비. 한글에 라틴 자간 규칙을 섞지 않음(§4.4) |

**의도적으로 피한 "AI 기본값":** 다크 배경 + 보라/시안 네온 강조, 가운데 정렬 히어로, `border-radius` 12~16px 카드 3열 그리드, pill 배지 남발, 유리질(backdrop blur) 패널, 모든 섹션에 동일한 fade-up 반복, 근거 없는 숙련도 % 막대(IA §7.3에서도 비권장).

## 1. 디자인 컨셉

**「조판된 낱장 — Composed Sheets」.** 이 사이트는 스크롤로 흘러가는 웹페이지가 아니라, 인쇄 조판대 위에서 **한 장씩 갈아 끼워지는 낱장**처럼 동작한다. 바탕은 형광 흰색이 아닌 미세하게 따뜻한 종이색이고, 텍스트는 차가운 잉크빛 먹색이며, 유일한 강조색은 교정지에 찍는 **주묵(朱墨) 붉은색** 하나뿐이다. 모서리는 전부 0 라운드 — 종이와 활자에는 둥근 모서리가 없다. 요소를 나누는 것은 카드 상자나 그림자가 아니라 **1px 괘선(hairline)과 넉넉한 여백**이며, 사이트 전체를 관통하는 반복 모티프는 **세리프 대형 숫자**(01/02/03, 연도, 프로젝트 인덱스)다. 인트로는 표지(表紙)라 내비게이션 없이 메뉴 세 줄이 화면을 지배하고, 나머지 세 뷰는 본문 낱장이라 좌측에 얇은 레일과 상단 내비를 공유해 "같은 인쇄물"임을 알린다. 인터랙션의 시그니처는 **괘선이 좌→우로 그어지는 것**과 **행 전체가 주묵으로 도장 찍히듯 채워지는 것** 두 가지로 통일한다.

## 3. 활자 (Typeface)

```css
--font-sans: 'Pretendard Variable', Pretendard, -apple-system, BlinkMacSystemFont,
             system-ui, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif;
--font-display: 'Instrument Serif', 'Apple SD Gothic Neo', 'Times New Roman', serif;
--font-mono: ui-monospace, SFMono-Regular, 'SF Mono', Menlo, Consolas, monospace;
```

| 활자 | 담당 범위 | 로드 방식 |
|---|---|---|
| **Pretendard Variable** | 모든 **한글** + 기본 라틴 본문 | CDN `<link>` — `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.css` (동적 서브셋: 한글 웹폰트 용량 문제를 서브셋 분할로 해결) |
| **Instrument Serif** | **숫자와 영문 병기 전용.** 01/02/03, 연도, 프로젝트 인덱스, 로고 이니셜, 이름(영문) | Google Fonts `<link>` (400 + 400italic) |
| 시스템 mono | 기간(`0000.00 – 0000.00`), 라벨, 태그, 캡션 | 로드 없음(시스템 스택) |

- **금지:** `--font-display`를 한글에 절대 적용하지 않는다(세리프 한글 폴백이 튀어 조판이 무너진다). 숫자·라틴만 이 폰트로 감싼 별도 요소(`<span class="num">`)에 적용한다.
- 모든 웹폰트에 `font-display: swap`(CDN CSS에 이미 포함) — FOIT 방지.
- 폰트 로딩 전후 레이아웃 이동(CLS)을 줄이기 위해, 대형 숫자를 담는 요소에는 고정 높이 또는 `min-height`를 준다.

### 4.2 한글 타이포그래피 원칙 (필수 준수)

1. **자간은 음수.** 한글은 글리프 자체가 정사각 폭이라 라틴 기본 자간(0 또는 양수)을 쓰면 벌어져 보인다. 본문 `-0.01 ~ -0.015em`, 제목은 클수록 더 좁게 `-0.03 ~ -0.045em`. 위 표의 값을 그대로 쓴다.
2. **행간은 라틴보다 넉넉히.** 한글은 어센더/디센더가 없어 글줄이 답답해 보인다 → 본문 `1.7~1.8`, 제목 `0.94~1.25`.
3. **`word-break: keep-all` 전역 적용.** 이것이 없으면 한글이 음절 단위로 잘려("포트폴리오 프로젝트를 진행했습니 / 다") 조판이 무너진다. 함께 `overflow-wrap: break-word`로 긴 URL만 예외 처리.
   ```css
   body { word-break: keep-all; overflow-wrap: break-word; }
   ```
4. **`text-wrap`으로 줄 균형.** 제목 `text-wrap: balance`(2~3줄 이하일 때 유효), 본문 `text-wrap: pretty`(외톨이 글자 방지).
5. **mono 라벨의 양수 자간은 라틴 전용.** `.label`이 한글을 담을 경우 `letter-spacing: 0`으로 재정의한다 — 한글에 `+0.06em`은 시각적으로 무너진다.
   ```css
   .label:lang(ko), .label--ko { font-family: var(--font-sans); letter-spacing: 0; }
   ```
6. **숫자는 항상 고정폭.** 기간·연도·카운터에 `font-variant-numeric: tabular-nums;` — 세로로 쌓이는 리스트/타임라인에서 자릿수가 흔들리지 않게.
7. **본문 컬럼 폭(measure)은 `em`으로.** 한글 1글자 ≈ 1em이므로 라틴의 `65ch` 관습이 통하지 않는다(`ch`는 숫자 0의 폭 ≈ 0.5em이라 절반으로 계산됨). 읽기 좋은 **한 줄 38~44자** = `--measure-prose: 40em`(17px 기준 ≈ 680px). 짧은 문장 블록은 `--measure-short: 28em`.

### 4.3 텍스트 기본 규칙

```css
html { -webkit-font-smoothing: antialiased; text-rendering: optimizeLegibility; }
h1,h2,h3,h4 { text-wrap: balance; }
p, li { text-wrap: pretty; max-width: var(--measure-prose); }
.num { font-family: var(--font-display); font-variant-numeric: tabular-nums; }
```

## 6. 공통 셸 — 4개 뷰를 "같은 사이트"로 묶는 장치

세 가지만으로 통일감을 만들고, 나머지는 뷰마다 다르게 둔다.

1. **좌측 레일 (≥1024px, V1·V2·V3에만).** 폭 56px. 위쪽에 그 뷰의 번호를 세리프 대형 숫자로(`01`/`02`/`03`), 아래로 세로 hairline이 내려가며 **스크롤 진행분만큼 주묵으로 채워진다.** 스크롤바를 감추는 대신 이것이 위치 표시자 역할을 겸한다. 모바일에서는 레일이 사라지고, 스크롤 컨테이너 상단에 2px 진행 라인으로 축소된다.
2. **정렬선 하나.** 뷰 헤더의 타이틀, 리스트 행의 인덱스, 타임라인 축, 산문 컬럼의 왼쪽 끝이 **모두 같은 x좌표**(`--gutter` + `--rail-w`)에서 시작한다. 뷰가 바뀌어도 텍스트 시작점이 흔들리지 않아 페이드 전환이 "같은 종이 위 교체"로 읽힌다.
3. **전역 내비.**
   - ≥1024px: 상단 64px 바. 좌측에 로고(이니셜 2자, display serif) — 클릭 시 V0. 우측에 3개 텍스트 링크. 현재 뷰는 **앞에 주묵 점(●) + ink 굵게**(밑줄은 링크/CTA 전용이라 활성 표시에 쓰지 않음). `aria-current="page"`.
   - <1024px: **하단 고정 3분할 바**(56px + `env(safe-area-inset-bottom)`). 엄지 도달성 우선, 상단은 뷰 타이틀에 양보. 각 칸에 mono 소형 번호 + 한글 라벨, 활성 칸은 상단 2px 주묵 선.
   - **V0에는 내비가 없다.** 표지에는 목차가 곧 화면이기 때문(§7.1). 대신 최상단에 hairline 한 줄과 좌측 영문 이름·우측 갱신 표기만 둔다.

## 7. 뷰별 레이아웃 스케치

각 뷰의 **스크롤 컨테이너 경계**를 먼저 정의한다(GSAP 스무스 스크롤 인스턴스가 붙는 지점).

### 7.0 스크롤 컨테이너 규격표 — developer 인계용

| 뷰 | 스크롤 **밖**(고정) | 스크롤 컨테이너 높이 | 데스크톱 기준 화면 점유율 | 인스턴스 |
|---|---|---|---|---|
| V0 | 전체 (스크롤 없음) | — | 100% 고정, `overflow: hidden` | 없음 |
| V1 | 상단 내비 64px + 뷰 헤더 `clamp(96px,12vh,160px)` | `1fr` = `calc(100svh - 64px - 헤더)` | **≈ 76%** | #1 |
| V1-D | 다이얼로그 상단 바 72px | `calc(88svh - 72px)` | 시트 높이의 **≈ 82%** | #2 (열릴 때 #1 정지) |
| V2 | 상단 내비 64px + 뷰 헤더 | `1fr` (V1과 동일 공식) | **≈ 76%** | #3 |
| V3 | 상단 내비 64px + 뷰 헤더 | `1fr` (V1과 동일 공식) | **≈ 76%** | #4 |

모바일(<1024px)에서는 상단 내비가 사라지고 하단 바 56px가 생기므로 스크롤 컨테이너는 `calc(100svh - 헤더 - 56px - safe-area)` ≈ **72%**.

**셸 골격**

```
body           height:100svh; overflow:hidden;   ← body 스크롤 절대 금지
└ .view        position:absolute; inset:0;  display:grid;
               grid-template-rows: var(--nav-h) auto 1fr;
  ├ .nav       (row1, 고정)
  ├ .view-head (row2, 고정 — 타이틀/부제/카운터, 하단에 hairline)
  └ .view-body (row3, 1fr)
      grid-template-columns: var(--rail-w) minmax(0, 1fr);
      ├ .rail          (고정, ≥1024)
      └ .scroll        ← 스무스 스크롤 인스턴스가 붙는 유일한 요소
```

**스크롤 영역의 시각적 구획 (4개 뷰 공통)**
- 뷰 헤더 하단에 `--rule` 1px → 여기부터 스크롤 영역임을 선언.
- 스크롤 컨테이너 **하단 48px에 종이색 그라디언트 페이드**(정적, 애니메이션 금지) → "아래에 더 있음" 신호.
- 콘텐츠 마지막에 `--space-3xl`(144px) 여백 → 마지막 항목이 화면 바닥에 붙지 않게.
- 네이티브 스크롤바 숨김(`scrollbar-width: none`) — 위치는 좌측 레일의 주묵 진행 라인이 대신한다.

### 7.1 [V0] 인트로 — 표지 · 100vh 고정 · 스크롤 없음

- **비율:** 데스크톱 12열 중 좌측 5 / 우측 7. 메뉴 3행이 **수평 58% × 수직 72%** 를 차지 → IA의 "메뉴가 곧 화면" 요구를 수치로 충족.
- 이름 블록은 좌측 컬럼 **하단 정렬**(baseline이 화면 중앙보다 아래) — 가운데 정렬 히어로 회피.
- 메뉴 행 내부: `grid-template-columns: [번호 88px] [라벨 1fr] [보조설명 auto] [화살표 32px]`, 세로 중앙 정렬, 행 사이 `--rule` 1px.
- **호버/포커스:** 행 전체가 주묵으로 좌→우 채워지고(§8) 텍스트가 종이색으로 반전, 화살표가 우측으로 8px 이동. 한 번에 한 행만.
- **모바일:** 상단 38svh = 이름+태그라인, 하단 62svh = 메뉴 3행 균등 분할(각 ≈ 20svh, 최소 88px). 전 폭 사용, 번호는 라벨 위 작은 mono로 강등. 하단 링크는 메뉴 아래 한 줄.
- **휠 동작 (IA 열린질문 #6 → 디자이너 권고안):** **스크롤하지 않되 무시하지도 않음.** 휠 입력 시 스테이지 전체가 ±8px만 스프링으로 밀렸다 돌아온다(300ms). "여기는 스크롤이 없는 화면"이라는 촉감을 주면서 입력이 먹통이라는 인상은 피한다. 휠로 V1에 자동 진입시키는 것은 **비권장**(의도치 않은 전환).

- **행 그리드(≥1024px):** `[인덱스 64px] [제목·요약·태그 1fr] [메타 200px] [썸네일 280px]`, 행 높이 168px, 세로 패딩 `--space-l`.

- **썸네일:** `aspect-ratio: 16/9`, 기본 `filter: grayscale(1) contrast(0.92)` → 호버 시 원색 복귀. **트랜지션(300ms)으로만 처리하고 스크럽 애니메이션에 절대 쓰지 않는다**(filter는 매 프레임 리샘플링 비용 발생 — gsap-scroll-motion 스킬 원칙).
- **태그는 pill 배지가 아니라 `·` 구분 mono 텍스트.** 최대 4개 표시 후 `+N`. 배지 상자를 없애는 것이 이 사이트의 조판 톤을 지키는 핵심.
- **호버 신호:** ① 인덱스 숫자가 주묵으로 ② "자세히 보기 →"가 우측 하단에 x −8→0 페이드인 ③ 썸네일 컬러 복귀 + `scale(1.03)`(이미지라 안전). 행 전체가 클릭 대상이며 `tabindex`/Enter/Space 지원, `focus-visible` 시 호버와 동일 상태 + 주묵 아웃라인.
- **필터 칩:** pill 금지. 텍스트 + 하단 2px 밑줄 토글(활성 = 주묵 밑줄 + `--accent-soft` 바탕).
- **태블릿(640~1023):** 썸네일 160px 유지, 메타는 제목 아래로 내려가 2행 구성.
- **모바일:** 세로 스택 — 16:9 썸네일 전 폭 → 인덱스+제목 → 요약 → 메타/태그. 여전히 박스 없이 hairline 구분. 행 높이 auto, 최소 터치 영역 확보.
- **0건 상태:** 리스트 자리에 "[등록된 항목이 없습니다]"를 `--ink-500` `--fs-body`로 좌측 정렬(가운데 정렬 금지 — 이 사이트의 정렬선을 유지).

- **빈 블록은 라벨까지 통째로 미출력**(IA §5.3) — 빈 라벨이 남으면 2열 조판이 깨진다.

- **모바일:** 폭 100vw / 높이 100svh 풀시트, 상단 바 유지, 2열 → 1열(라벨이 본문 위 mono 소형으로 이동). 닫기 X는 최소 44×44px.

```
│  ┃   │  고정) │┃│ 키워드 A · 키워드 B     ▸ 프로젝트 A 보기 (주묵)     │
│  ┃   │        │ │                                                    │
│  ┃   │        │◆│ 0000.00      [자격증명 A]         ← Tier 2 (주묵)  │
│  ┃   │        │┆│                                                    │
│  ┃   │        │○│ 0000.00      [활동명 A]           ← Tier 3 (점선)  │
│  ┃   │ 0000   │┆│ ...                                                │
│  ┋   │ ▔▔▔▔  │ │                                                    │
│      │        │ │ [여기서부터 시작했습니다]     작업물 보기 →          │
└──────┴────────┴─┴────────────────────────────────────────────────────┘
        96px    축   본문 max 760px
```

- **그리드(≥1024px):** `[연도 96px] [축 24px] [본문 minmax(0, 760px)]`. 연도 열은 `position: sticky; top: 0` — 스크롤하면 그 해가 좌상단에 붙어 있다가 다음 해가 밀어낸다. **이 sticky 밀어내기가 V2만의 시그니처 리듬**이며 V1/V3에는 존재하지 않는다.
- **sticky는 CSS로만.** GSAP `pin`을 쓰지 않는다(gsap-scroll-motion 스킬 권고 — pin은 레이아웃을 재구성해 스무스 스크롤 컨테이너와 충돌 위험).
- 연도는 `--fs-num-xl` display serif, `--ink-300`. 현재 화면에 걸린 연도만 `--ink`로 진해진다.

#### 유형 6종의 3단계 위계 (IA §6.2 요청 대응)

색을 6개 쓰지 않는다. **마커 형태 + 축 굵기 + 활자 크기**의 3축으로 3단계를 만들고, 같은 단계 안의 두 유형은 **텍스트 라벨**로만 구분한다.

| 단계 | 포함 유형 | 의미 | 마커 | 축 세그먼트 | 제목 크기 | 색 |
|---|---|---|---|---|---|---|
| **T1 — 궤적** | 경력, 학력 | 기간을 두고 몸담은 것. 타임라인의 뼈대 | ● 채운 원 10px | `2px` 실선 `--rule-strong` | `--fs-h3` (20px) | `--ink` |
| **T2 — 증명** | 수상, 자격 | 특정 시점에 획득한 성취 | ◆ 45° 회전 사각 8px | `1px` 실선 `--rule` | 17px | 마커만 `--accent` |
| **T3 — 축적** | 교육, 활동 | 곁가지로 쌓은 경험 | ○ 빈 원 8px (`--ink-300` 1px 테두리) | `1px` **점선** | 16px | `--ink-700` |

- 유형명(`경력`/`학력` 등)은 기간 옆에 `--fs-label` mono 라벨로 항상 노출 — 형태만으로 6종을 구분하려 들지 않는다.
- `featured: true` 항목: 제목을 `--fs-h2`로 올리고 본문 좌측에 3px 주묵 세로 바 + `--accent-soft` 워시. **강조 플래그가 있는 항목에만** 적용(색깔 border-left 콜아웃 남용 금지).
- 연결 프로젝트(`projectIds`)는 주묵 텍스트 링크 `▸ [프로젝트명] 보기` — 클릭 시 V1-D 다이얼로그가 **V2 위에 그대로 열린다**(뷰 전환 아님).
- **모바일:** 축을 좌측 20px로 당기고 연도는 축 위 가로 배지형 표식으로 전환(sticky 유지). 본문 전 폭.

### 7.5 [V3] 자기소개 — 산문 · 단일 컬럼 + 좌측 이탈

**리듬: 읽는 화면. 좌우 비대칭, 번호와 인용이 컬럼 밖으로 삐져나옴.**

```
┌ nav ────────────────────────────────────────────────────────────────┐
├ view-head : 자기소개 / [부제] ──────────────────────────────────────┤
├──────┬──────────────────────────────────────────────────────────────┤
│ rail │  [스스로를 소개하는             ┌──────────┐                 │
│  03  │   한 문장을                     │  1:1     │  ← 프로필 220px │
│  ┃   │   입력하세요]  display-l        │ 프로필   │     우측 배치    │
│  ┃   │  [이름] · [직군]  label         └──────────┘                 │
│  ┃   │                                                              │
│  ┃   │  [어떤 일을 해왔고 무엇에 관심이 있는지 3~5문장으로]  ← 40em   │
│  ┃   │  ──────────────────────────────────────────────  rule       │
│  ┃   │ 01                                                           │ ← 번호가 컬럼
│  ┃   │  │ [강점 1]              h3                                  │   왼쪽으로 이탈
│  ┃   │  │ [이 강점을 뒷받침하는 경험을 한두 문장으로]                 │   (hanging)
│  ┃   │ 02 ─────────────────────────────────────────  rule-faint    │
│  ┃   │  │ [강점 2] ...                                              │
│  ┃   │  ──────────────────────────────────────────────             │
│  ┃   │  [카테고리 A]  │ 기술 A · 기술 B · 기술 C                     │ ← 라벨/값 2열
│  ┃   │  [카테고리 B]  │ 툴 D · 툴 E                                  │   (숙련도 표기 없음)
│  ┋   │                                                              │
│      │「[작업할 때 지키는 원칙 한 줄]」  ← 좌측으로 outdent, display-l │
│      │  ──────────────────────────────────────────────             │
│      │  [함께 이야기하고 싶다면 연락 주세요]                          │ ← 연락 블록
│      │  ✉ [이메일 주소]                    ← 주 CTA, 대형 타이포     │   paper-raised
│      │  GitHub · 링크 A · 이력서 PDF ↓     ← 보조, mono small        │
└──────┴──────────────────────────────────────────────────────────────┘
```

- **인사 블록은 좌우 비대칭.** 좌측에 3~4행짜리 대형 인사 문장(`--fs-display-l`), 우측 상단에 1:1 프로필 220px. 가운데 정렬 금지, 프로필이 주인공이 되지 않게 크기를 억제.
- **강점은 카드 그리드가 아니다.** 세로로 쌓인 산문 항목이며, `--fs-num-m` 세리프 번호가 컬럼 좌측 여백으로 **hanging** 처리되어 밖으로 걸린다(`margin-left: -64px` 상당, ≥1024px에서만). 항목 사이 `--rule-faint`.
- **스택은 라벨/값 2열.** 배지 상자 없이 `·` 구분 텍스트. **숙련도 표기는 없음**(IA §7.3 기본값 채택 — 근거 없는 % 막대 금지).
- **인용 한 줄은 outdent.** 본문 컬럼보다 좌측으로 32px 삐져나오고 `--fs-display-l`. 산문의 균질한 리듬을 한 번 깨는 유일한 지점.
- **연락 영역(사이트 최종 CTA):** `--paper-raised` 바탕 + 상단 2px 주묵 괘선. 이메일이 대형 타이포 링크(`clamp(1.75rem, 3.4vw, 3rem)`)로 시각적 무게를 독점하고, 나머지(GitHub/링크/이력서)는 `--fs-label` mono 링크로 강등 — IA §8의 "주 CTA는 사이트 전체에서 하나" 규칙을 시각 위계로 강제.
- 이력서 PDF가 없으면 항목 자체를 렌더링하지 않는다(IA §7.5).
- **모바일:** 프로필 1:1을 인사 문장 위 96px로 축소·좌측 정렬. hanging 번호는 컬럼 안으로 복귀(라벨 위 인라인). outdent 인용은 들여쓰기 0으로 정렬.

## 8. 모션 컨셉

> 실제 GSAP 구현은 developer 담당. 여기서는 **무엇이 어떻게 보여야 하는가**까지만 정의한다.

### 8.1 전역 원칙

1. **`opacity`와 `transform`만 애니메이션한다.** `filter`(grayscale/blur), `box-shadow`, `background-position`은 **단발 CSS 트랜지션에서만** 허용하고 스크럽(스크롤 연동 매 프레임)에는 절대 쓰지 않는다.
2. **등장 애니메이션은 `once: true`.** 화면 단위 뷰라 같은 영역을 위아래로 오가는 일이 잦다 — 되감기(reverse)는 산만하다.
3. **트리거는 부모 하나에.** 항목마다 ScrollTrigger를 만들지 않고 스크롤 컨테이너/블록 단위 트리거 + `stagger`로 처리.
4. **이징:** 등장 `power3.out`, 퇴장 `power2.in`, 호버 `cubic-bezier(.2,.7,.2,1)`. 스프링/바운스 금지(조판 톤과 상충).
5. **`prefers-reduced-motion: reduce`:** 모든 등장 모션과 패럴랙스 제거(즉시 최종 상태). 단 **뷰 전환은 120ms 크로스페이드만 유지** — 완전 즉시 교체는 어디로 갔는지 알 수 없게 만든다.

### 8.2 뷰 전환 (공통, 4개 뷰 전부)

| 단계 | 대상 | 값 | 시간 | 이징 |
|---|---|---|---|---|
| 1 | 나가는 뷰 | `opacity 1→0`, `y 0→-12px` | 220ms | `power2.in` |
| 2 | 들어오는 뷰 | `opacity 0→1`, `y 16→0` | 320ms | `power3.out` |
| 겹침 | — | 2단계는 1단계 시작 후 **160ms 지점**에 시작 | — | — |
| 3 | 들어온 뷰의 첫 화면 요소 | 뷰별 등장 스태거(§8.4~) | +80ms 지연 | — |

- 전환 중 **바탕(`--paper`)은 절대 바뀌지 않는다** — 화면이 깜빡이지 않고 "종이 위에서 내용만 교체"되는 인상.
- 스크롤 위치는 복원하지 않고 **항상 상단부터**(IA §1.1).
- 좌측 레일의 번호(`01`→`02`)는 뷰와 함께 페이드되지 않고 **숫자만 세로로 밀려 교체**(y ±20px 크로스페이드, 240ms) — 레일이 연속된 축임을 드러낸다.

### 8.3 [V0] 인트로

**최초 로드 시퀀스 (총 ≈1.4s)**

| 순서 | 요소 | 동작 | 시간 |
|---|---|---|---|
| 1 | 종이 바탕 | opacity 0→1 | 120ms |
| 2 | 이름 (display-xl) | **마스크 업** — `overflow:hidden` 래퍼 안에서 `y 100%→0` | 640ms `power3.out` |
| 3 | 직군 / 태그라인 | `opacity + y 12→0`, stagger 80ms | 400ms |
| 4 | **메뉴 3행의 괘선** | `scaleX 0→1`, `transform-origin: left` — **좌→우로 선이 그어짐**, stagger 90ms | 400ms |
| 5 | 메뉴 행 텍스트 | 괘선 뒤를 따라 `opacity + x -12→0`, stagger 90ms | 320ms |
| 6 | 상단/하단 바 | opacity 0→1 | 240ms |

**괘선이 좌→우로 그어지는 것(4)이 이 사이트의 시그니처 모션**이며, V1 행 구분선·V2 축·V3 블록 구분선에서 같은 원리로 반복된다.

**호버/포커스 (메뉴 행)**
- 행 배경 `::before`가 `scaleX 0→1` (`origin: left`), 320ms — **도장이 찍히듯 주묵이 행을 채움**.
- 동시에 텍스트 색 `--ink`→`--accent-ink` (180ms), 화살표 `x 0→8px`.
- 커서가 빠질 때는 `origin: right`로 되감겨 **들어온 방향과 나가는 방향이 다르다**(움직임에 방향성을 부여하는 디테일).
- 키보드 `:focus-visible`도 동일 상태 + 2px 주묵 아웃라인(offset 2px).

**휠 입력:** 스테이지 전체 `y ±8px` 스프링 후 300ms 내 복귀. 스크롤 없음을 알리는 촉감 피드백.

### 8.4 [V1] 포트폴리오

- **뷰 진입:** 뷰 헤더 → 행 스태거(`opacity 0→1`, `y 24→0`, stagger 50ms). 화면에 보이는 앞 6~8행까지만 시퀀스로 처리하고 나머지는 스크롤 트리거에 위임.
- **스크롤 등장:** 스크롤 컨테이너에 트리거 하나, `start: 'top 88%'`, `once: true`. 행마다 트리거를 만들지 않는다.
- **호버:** 배경 `--paper-raised` 페이드(160ms) / 인덱스 숫자 색 전환(160ms) / 썸네일 `grayscale(1)→0` + `scale(1.03)` (300ms CSS 트랜지션) / "자세히 보기 →" `x -8→0` 페이드인(200ms).
- **좌측 레일 진행 라인:** 스크롤 진행률에 `scaleY` 연동(`transform-origin: top`). 스크럽이지만 transform 단일 속성이라 안전.

### 8.5 [V1-D] 다이얼로그

| 단계 | 동작 | 시간 |
|---|---|---|
| 열림 ① | 배경막 `opacity 0→1` | 180ms |
| 열림 ② | 시트 `opacity 0→1`, `y 24→0`, `scale .985→1` | 360ms `power3.out` |
| 열림 ③ | 시트 안착 60ms 후 내부 블록 `opacity + y 16→0`, stagger 40ms | 300ms |
| 닫힘 | 시트 `opacity 1→0`, `y 0→12` → 배경막 페이드 | 220ms `power2.in` |
| 이전/다음 | **시트는 고정**, 내부 콘텐츠만 `x ∓16 + fade` 교체 + 내부 스크롤 즉시 top 리셋 | out 200 / in 260ms |

- 시트의 `scale`은 텍스트를 포함하지만 **단발 트랜지션이라 허용**한다(스크럽이 아니므로 서브픽셀 재래스터화가 한 번만 발생). 스크롤 연동 scale은 여전히 금지.
- 열리는 순간 배경 V1의 스무스 스크롤 인스턴스를 **정지**시키고, 닫으면 재개하며 **원래 스크롤 위치를 그대로 유지**한다(IA §1.1).

### 8.6 [V2] 연혁

| 순서 | 요소 | 동작 |
|---|---|---|
| 1 | 세로 축 | `scaleY 0→1`, `origin: top` — **위에서 아래로 축이 그어짐**, 700ms |
| 2 | 마커 | 축을 따라 `scale 0→1` 순차 pop, stagger 60ms (텍스트 없는 도형이라 scale 안전) |
| 3 | 항목 텍스트 | `opacity + x -16→0`, 마커보다 40ms 늦게 |
| 스크롤 중 | 활성 연도/마커 | 뷰포트 중앙에 걸린 항목의 마커·연도가 색만 전환(`--ink-300`→`--ink`/`--accent`), 200ms. **`toggleClass`로 처리하고 scrub 금지** |
| sticky 연도 | — | CSS `position: sticky`만 사용. GSAP `pin` 사용 금지 |

### 8.7 [V3] 자기소개

| 요소 | 동작 |
|---|---|
| 인사 문장 | **줄 단위 마스크 업** (3~4줄, `y 100%→0`, stagger 80ms) — V0 이름과 같은 어법이라 사이트 정체성이 연결된다 |
| 1:1 프로필 | `opacity 0→1` + `scale 1.04→1` (이미지 요소, 안전), 500ms |
| 이후 블록 | 스크롤 트리거 `opacity + y 24→0`, **블록 단위**(개별 문장 아님), `once: true` |
| 강점 hanging 번호 | 블록 등장보다 100ms 늦게 `opacity 0→.6`, `x -12→0` |
| 인용 outdent | `x -24→0` + fade — 옆에서 밀려 들어옴 |
| 연락 이메일 | 진입 시 밑줄 `scaleX 0→1` (좌→우, 500ms) — §8.3의 괘선 어법 재사용 |

## 9. 컴포넌트 세부 규격

### 9.1 이미지 · 플레이스홀더

| 항목 | 규격 |
|---|---|
| 프로젝트 이미지 | `aspect-ratio: 16/9`, `object-fit: cover`, 권장 1600×900 |
| 프로필 이미지 | `aspect-ratio: 1/1`, 권장 800×800 |
| **다른 비율 금지** | IA §10에 따라 이 두 가지만 사용. 갤러리에서 4:3을 쓸 경우 그 프로젝트 전체를 4:3으로 통일 |
| 플레이스홀더 | `--paper-raised` 바탕 + `--rule` 1px 테두리 + 중앙에 프로젝트 이니셜(display serif, `--ink-300`, 24px) + 좌하단 mono 소형 `16 : 9` 표기 |
| 이미지 없음 | **비율 박스는 그대로 유지**하고 플레이스홀더만 표시 → 레이아웃 파손 없음(QA 대응) |
| 로딩 | `loading="lazy"` + `decoding="async"`. 이미지 로드 후 `ScrollTrigger.refresh()` 필요(높이 변동) |

### 9.2 링크 · 버튼

라운드 0, 그림자 없음. 3종만 존재한다.

| 종류 | 형태 | 사용처 |
|---|---|---|
| **주 CTA** | 대형 텍스트 + 밑줄이 좌→우로 그어짐(호버 500ms). 채운 버튼 상자 아님 | V3 이메일 (사이트 전체 1개) |
| **보조 링크** | 텍스트 + ` →`, 호버 시 화살표 `x +4px` + 색 `--accent` | "연혁 보기 →", "자세히 보기 →", 외부 링크 |
| **메타 링크** | `--fs-label` mono, 호버 시 밑줄만 | 하단 링크, 이력서, 갤러리 캡션 내 링크 |

### 9.3 포커스 · 접근성

```css
:focus-visible {
  outline: var(--rule-w-strong) solid var(--accent);
  outline-offset: 2px;
  border-radius: 0;
}
```
- 마우스 클릭엔 링이 안 보이고 키보드에만 보이도록 `:focus-visible` 사용.
- 모바일 터치 타겟 최소 `44×44px`(`--tap-min`), 특히 다이얼로그 닫기 X와 하단 내비 3분할 칸.
- 대비: 모든 텍스트 조합이 AA(4.5:1) 이상 — §2.1 표에 실측 수치 기재. `--ink-300`은 **비텍스트 전용**.
- 다이얼로그: `role="dialog" aria-modal="true"`, 포커스 트랩, `Esc` 닫기, 닫을 때 트리거 행으로 포커스 복귀(IA §5.5).
- 현재 뷰 내비 항목에 `aria-current="page"`.
- 색만으로 정보를 전달하지 않는다 — 연혁 3단계 위계도 **형태(●◆○) + 텍스트 라벨**을 함께 쓴다(§7.4).

## 11. developer 인계 체크리스트

- [ ] `:root`에 §2·§4·§5의 모든 토큰 선언. **CSS 본문에 HEX/px 직접 기입 금지**(브레이크포인트 미디어쿼리 값은 예외).
- [ ] `body { height:100svh; overflow:hidden; word-break:keep-all; }` — body 스크롤 절대 금지.
- [ ] 뷰마다 스크롤 컨테이너는 **정확히 하나**(§7.0 표). 스무스 스크롤 인스턴스도 컨테이너당 하나.
- [ ] 다이얼로그 열림 시 배경 인스턴스 **정지**, 닫힘 시 재개 + 스크롤 위치 유지.
- [ ] 스크롤바 숨김 + 좌측 레일 주묵 진행 라인(`scaleY` 스크럽)으로 대체.
- [ ] 애니메이션 속성은 `opacity`/`transform`만. `filter: grayscale`은 **호버 CSS 트랜지션에서만**.
- [ ] `prefers-reduced-motion` 분기 — 등장 모션 제거, 뷰 전환 120ms 크로스페이드는 유지.
- [ ] 한글 조판 3종 세트: `word-break: keep-all` / 음수 자간 / `tabular-nums`.
- [ ] mono 라벨이 한글일 때 `letter-spacing: 0` 재정의 규칙 적용.
- [ ] 이미지 로드 후 `ScrollTrigger.refresh()`.
- [ ] `--radius: 0` — 어떤 요소에도 둥근 모서리를 만들지 않는다.
- [ ] 그림자는 다이얼로그 시트 1곳뿐.
- [ ] 빈 필드는 DOM 자체를 생성하지 않는다(빈 라벨·비활성 버튼 잔존 금지).
