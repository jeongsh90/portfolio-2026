# 사용자 요청 (2026-08-23, 최종본 — 두 번째 메시지로 갱신됨)

## 필요기능
- **페이지 전환 시 페이드** — 인트로 ↔ 포트폴리오/연혁/자기소개 각 "뷰" 간 전환, 그리고 포트폴리오 리스트 → 상세(다이얼로그) 전환에 페이드 적용.
- **스무스 스크롤링(GSAP), 모든 스크롤 요소에 적용** — 브라우저 네이티브 스크롤이 아니라 GSAP 기반 부드러운 스크롤을 모든 스크롤 가능한 영역(포트폴리오 리스트, 연혁 타임라인, 상세 다이얼로그 내용 등)에 일관되게 적용한다.

> 참고: 최초 메시지엔 "단일 링크로 구성(진짜 페이지 이동 없이 JS로 뷰 전환)"이 있었으나, 두 번째(갱신) 메시지에서 이 항목이 빠지고 "스무스스크롤링"으로 대체되어 전달됨. 빌드 도구/백엔드가 없는 정적 사이트 특성상 실제 서버 라우팅은 어차피 불필요하므로, 단일 HTML 문서 + JS 기반 뷰 전환(+선택적으로 해시 앵커로 딥링크만 지원) 구조를 유지하는 것이 합리적 기본값이라 판단하고 그대로 진행함 — 사용자가 명시적으로 다중 HTML 파일을 원하면 후속 피드백으로 조정.

## 페이지 구조 (트리)
- 인트로 페이지 (첫 진입 화면 — 루트)
  - 포트폴리오
    - 포트폴리오 리스트 (프로젝트 목록)
    - 포트폴리오 상세화면 (다이얼로그/모달로 표시)
  - 연혁 (경력/이력 타임라인)
  - 자기소개 (About)

## 확정된 제약
- 콘텐츠(프로젝트 이력, 소개글 등)는 아직 없음 — 플레이스홀더로 구조부터 만든다.
- 스택: HTML + CSS + JavaScript + GSAP. 빌드 도구/프레임워크 없음.
- Git: 로컬 init + GitHub 원격 연결까지 진행. 저장소 이름/공개여부는 사용자에게 재확인 필요.

## 오케스트레이터 실행 메모
- 이 세션에는 TeamCreate/TaskCreate(에이전트 팀 통신 도구)가 제공되지 않아, portfolio-landing-orchestrator 스킬이 정의한 "에이전트 팀 모드"를 문자 그대로 실행할 수 없었다. 대신 동일한 파이프라인·데이터 흐름(_workspace 파일 기반 인계)을 서브 에이전트(Agent 도구, 순차 호출)로 구현해 진행한다 — 스킬 자체는 수정하지 않음(팀 도구가 제공되는 환경에서는 정의된 대로 팀 모드로 동작 가능).
