## 1. 전체 뷰 맵

사용자가 확정한 트리를 그대로 따른다. **스크롤로 이어지는 하나의 롱폼 페이지가 아니라, 페이드로 교체되는 4개의 독립 화면**이다.

```
[V0] 인트로 (루트 / 첫 진입)
  ├── [V1] 포트폴리오 ── 리스트(스크롤)
  │        └── [V1-D] 상세 (다이얼로그 오버레이 — V1 위에 뜸, 뷰 교체 아님)
  ├── [V2] 연혁 (타임라인, 스크롤)
  └── [V3] 자기소개 (About, 스크롤)
```

| ID | 뷰 이름 | 해시 경로 | 목적 (한 줄) | 스크롤 |
|----|---------|-----------|--------------|--------|
| V0 | 인트로 | `#/` 또는 `#/intro` | "누구이고 무엇을 하는 사람인지"를 한 화면에 각인시키고, 3개 뷰로 가는 문을 연다 | 없음 (100vh 고정) |
| V1 | 포트폴리오 | `#/portfolio` | 대표 작업물을 목록으로 훑게 하고, 관심 항목을 상세로 열게 한다 | 있음 (세로) |
| V1-D | 포트폴리오 상세 | `#/portfolio/{id}` | 한 프로젝트의 맥락·역할·결과를 깊게 전달한다 | 있음 (다이얼로그 내부) |
| V2 | 연혁 | `#/history` | 시간 순서로 쌓아온 경력·이력을 신뢰 가능한 흐름으로 보여준다 | 있음 (타임라인) |
| V3 | 자기소개 | `#/about` | 결과물 뒤에 있는 사람의 관점·강점·연락 수단을 전달한다 | 있음 (세로) |

### 1.1 뷰 전환 규칙

- **전환 방식:** 이전 뷰 페이드아웃 → 다음 뷰 페이드인 (겹침 구간 짧게). 전환 중 스크롤 위치는 **각 뷰별로 기억**했다가 복귀 시 복원하지 않고 **항상 상단부터** 시작한다(화면 단위 이동이라는 인상을 유지).
- **가능한 이동:** V0 ↔ V1 / V0 ↔ V2 / V0 ↔ V3, 그리고 V1 ↔ V2 ↔ V3 (인트로를 거치지 않고 직접 전환 가능 — §2.1 전역 내비게이션).
- **V1-D는 뷰 전환이 아니다.** V1이 배경에 남은 채 다이얼로그가 페이드+미세 스케일로 올라온다. 닫으면 V1의 **원래 스크롤 위치 그대로** 복귀한다.
- **뒤로가기:** 브라우저 뒤로가기는 해시 이력을 따라 직전 뷰(또는 다이얼로그 닫힘)로 동작해야 한다.

### 1.2 각 뷰의 화면 완결성 원칙

각 뷰는 인트로를 보지 않고 딥링크로 바로 진입해도 이해되도록, 다음 3요소를 **자체적으로** 갖는다:

1. 뷰 타이틀 + 한 줄 설명 (그 뷰가 무엇인지)
2. 전역 내비게이션 (다른 뷰로 나가는 길)
3. 뷰 하단의 다음 행동 유도 (§8 CTA 맵)

## 2. 공통 요소 명세

### 2.1 전역 내비게이션 (V1·V2·V3에 상주, V0은 별도 형태)

| 필드명 | 설명 | 반복 | 플레이스홀더 예시 |
|--------|------|------|-------------------|
| 로고/이름 마크 | 좌상단. 클릭 시 인트로(V0)로 복귀 | 1 | `[이름]` 또는 이니셜 2자 `AB` |
| 메뉴 항목 | 포트폴리오 / 연혁 / 자기소개 3개 고정. 현재 뷰는 활성 표시 | 3 (고정) | "포트폴리오", "연혁", "자기소개" |
| 인트로로 돌아가기 | 로고와 별개로 명시적 항목을 둘지는 디자이너 판단 | 0~1 | "← 처음으로" |

- 모바일: 3개뿐이므로 햄버거 없이 **하단 고정 바 또는 상단 인라인 3분할**로 처리 권장(디자이너 결정).
- 접근성: 현재 뷰 항목에 `aria-current="page"`.

### 2.2 뷰 헤더 (V1·V2·V3 공통 골격)

| 필드명 | 설명 | 반복 | 길이 기준 | 플레이스홀더 예시 |
|--------|------|------|-----------|-------------------|
| 뷰 타이틀 | 큰 제목 | 1 | 2~6자 | "포트폴리오" |
| 뷰 부제 | 이 화면에서 볼 수 있는 것 | 1 | 1문장, 30~50자 | "[이 화면에서 보여줄 내용을 한 문장으로 입력하세요]" |
| 카운터 | 항목 수 표시(선택) | 0~1 | — | "총 00건" |

### 2.3 스크롤 정책

- 스크롤이 발생하는 영역: **V1 리스트, V1-D 다이얼로그 본문, V2 타임라인, V3 본문** — 전부 GSAP 기반 스무스 스크롤 적용 대상.
- V0은 스크롤이 없어야 한다(100vh 안에서 완결). 인트로에서 휠을 굴렸을 때의 반응(무시 / 미세 패럴랙스 / 포트폴리오로 진입)은 **디자이너·개발자가 결정**할 여지로 남긴다.
- 다이얼로그가 열린 동안 배경(V1) 스크롤은 잠근다 — 스크롤 체이닝 금지.

### 2.4 상태·엣지 케이스 (모든 리스트 공통)

| 상태 | 필요 문구 |
|------|-----------|
| 항목 0개 | "[등록된 항목이 없습니다]" |
| 이미지 없음 | 비율 유지 플레이스홀더 블록 + 프로젝트명 이니셜 |
| 링크 없음 | 버튼 자체를 숨김(비활성 회색 버튼을 남기지 않음) |

## 3. [V0] 인트로

**목적:** 첫 화면에서 정체성을 각인하고, 3개 뷰 중 하나를 고르게 한다.
**구성:** 100vh 한 화면, 스크롤 없음. 정보 밀도를 낮게 유지(등장 모션이 살아야 함).

| # | 필드명 | 설명 | 반복 | 길이 기준 | 플레이스홀더 예시 |
|---|--------|------|------|-----------|-------------------|
| 1 | 이름 | 메인 타이포. 화면 최대 크기 요소 | 1 | 2~12자 | `[이름을 입력하세요]` |
| 2 | 이름(영문) | 이름 위/아래 작은 병기. 선택 | 0~1 | 2~20자 | `[NAME]` |
| 3 | 직군 한 줄 | 무엇을 하는 사람인지 | 1 | 10~24자 | `[직군 / 하는 일을 한 줄로]` |
| 4 | 태그라인 | 핵심 가치 제안 한 문장 | 1 | 1문장, 30~60자 | `[어떤 문제를 어떻게 푸는 사람인지 한 문장으로 입력하세요]` |
| 5 | 진입 메뉴 | 포트폴리오/연혁/자기소개 3개 대형 항목. **인트로의 주 인터랙션** | 3 (고정) | — | §3.1 |
| 6 | 갱신 표기 | 최종 업데이트 시점(선택) | 0~1 | — | "Last updated · 0000.00" |
| 7 | 하단 링크 | 이메일 / 외부 링크 아이콘 (선택, 최대 4) | 0~4 | — | "Email", "GitHub", "링크 A" |

### 3.1 진입 메뉴 항목 (반복 3회, 순서 고정)

| 필드명 | 설명 | 플레이스홀더 예시 |
|--------|------|-------------------|
| 번호/인덱스 | 01 / 02 / 03 | "01" |
| 메뉴 라벨 | 뷰 이름 | "포트폴리오" / "연혁" / "자기소개" |
| 보조 설명 | 그 뷰에 무엇이 있는지 한 조각 | "작업물 00건" / "0000 – 현재" / "저에 대해" |
| 이동 대상 | 해시 경로 | `#/portfolio` / `#/history` / `#/about` |

> **디자이너 참고:** 이 3개 항목이 인트로의 시각적 중심이다. 작은 상단 GNB 형태로 축소하지 말 것 — 인트로는 "메뉴가 곧 화면"인 구조.

## 4. [V1] 포트폴리오 — 리스트

**목적:** 여러 작업물을 빠르게 훑고, 관심 항목을 상세(V1-D)로 열게 한다.
**구성:** 뷰 헤더 + (선택)필터 + 항목 리스트(스크롤) + 하단 마감 영역.

### 4.1 리스트 항목 필드 (반복 3~12개, 기본 6개)

| # | 필드명 | 설명 | 필수 | 길이/규격 | 플레이스홀더 예시 |
|---|--------|------|------|-----------|-------------------|
| 1 | id | 딥링크·다이얼로그 매칭용 식별자 | 필수 | 영문 소문자+숫자 | `project-a` |
| 2 | 인덱스 번호 | 목록 순번 표기 | 선택 | 2자리 | "01" |
| 3 | 프로젝트명 | 항목 제목 | 필수 | 4~24자 | `프로젝트 A` |
| 4 | 한 줄 요약 | 무엇을 만들었고 왜 만들었는지 | 필수 | 1문장, 30~50자 | `[이 프로젝트가 해결한 문제를 한 문장으로 입력하세요]` |
| 5 | 기간 | 표시용 짧은 기간 | 필수 | `YYYY.MM–YYYY.MM` | `0000.00 – 0000.00` |
| 6 | 역할 | 담당 역할 한 조각 | 필수 | 4~16자 | `[담당 역할]` |
| 7 | 기술·툴 태그 | 배지 | 필수 | 3~6개, 각 2~12자 | `기술 A`, `기술 B`, `툴 C` |
| 8 | 카테고리 | 필터·분류용 | 선택 | 2~8자 | `카테고리 A` |
| 9 | 썸네일 | 목록 이미지 | 선택 | **16:9**, 권장 1600×900 | `assets/placeholder-16x9.svg` |
| 10 | 대표 색상 | 항목별 강조색(모션·호버용) | 선택 | HEX | `#000000` |

**항목 인터랙션:** 항목 전체가 클릭 대상(카드/행 어디를 눌러도 상세 열림). 키보드 접근 가능해야 하며(Enter/Space), 호버 시 상세로 이어진다는 신호(예: "자세히 보기 →")를 준다.

### 4.2 리스트 상단 부가 요소

| 필드명 | 설명 | 반복 | 플레이스홀더 예시 |
|--------|------|------|-------------------|
| 필터 칩 | 카테고리별 필터. **항목 6개 미만이면 생략 권장** | 0~5 | "전체", "카테고리 A", "카테고리 B" |
| 정렬 표기 | "최신순" 등 고정 텍스트로만 표기(기능 없이) | 0~1 | "최신순" |

### 4.3 리스트 하단 마감

| 필드명 | 설명 | 플레이스홀더 예시 |
|--------|------|-------------------|
| 마감 문구 | 목록 끝을 알리는 한 줄 | "[더 궁금한 작업이 있다면 연락 주세요]" |
| 다음 뷰 유도 | 연혁 또는 자기소개로 넘기는 링크 | "연혁 보기 →" |

## 5. [V1-D] 포트폴리오 상세 (다이얼로그)

**목적:** 한 프로젝트의 배경–역할–과정–결과를 충분히 전달한다.
**구성:** V1 위에 뜨는 모달. 내부 스크롤. 닫기는 X 버튼 / 배경 클릭 / `Esc` 모두 지원.

### 5.1 헤더 영역

| # | 필드명 | 설명 | 필수 | 길이/규격 | 플레이스홀더 예시 |
|---|--------|------|------|-----------|-------------------|
| 1 | 프로젝트명 | 다이얼로그 타이틀 (`aria-labelledby` 대상) | 필수 | 4~24자 | `프로젝트 A` |
| 2 | 한 줄 요약 | 리스트와 동일 값 재사용 | 필수 | 30~50자 | `[한 줄 요약]` |
| 3 | 대표 이미지 | 상단 히어로 이미지 | 선택 | **16:9** | `assets/placeholder-16x9.svg` |
| 4 | 닫기 버튼 | X 아이콘 | 필수 | — | `aria-label="닫기"` |

### 5.2 메타 정보 블록 (라벨–값 목록)

| 필드명 | 설명 | 필수 | 플레이스홀더 예시 |
|--------|------|------|-------------------|
| 기간 | 시작–종료 (진행 중이면 "현재") | 필수 | `0000.00 – 0000.00` |
| 역할 | 담당 역할. 복수 가능 | 필수 | `[담당 역할]`, `[담당 역할 2]` |
| 소속/유형 | 회사 프로젝트·개인·팀·외주 등 유형 | 선택 | `[프로젝트 유형]` |
| 팀 구성 | 인원 규모·구성 | 선택 | `[예: 0명 (직군 구성)]` |
| 기여도 | 본인 담당 비중 | 선택 | `[00%]` |
| 사용 기술·툴 | 태그 나열 | 필수 | `기술 A`, `기술 B`, `툴 C` |

### 5.3 본문 블록 (순서 고정, 각 블록은 비어 있으면 통째로 숨김)

| # | 블록명 | 설명 | 길이 기준 | 플레이스홀더 예시 |
|---|--------|------|-----------|-------------------|
| 1 | 개요 | 프로젝트가 무엇인지 | 2~4문장 | `[프로젝트의 목적과 배경을 2~4문장으로 입력하세요]` |
| 2 | 문제 / 배경 | 왜 필요했는지 | 2~3문장 | `[해결하려던 문제를 입력하세요]` |
| 3 | 나의 역할 | 무엇을 직접 했는지. **불릿 권장** | 3~5개 불릿 | `[담당한 작업을 항목으로 입력하세요]` |
| 4 | 접근 / 과정 | 어떻게 풀었는지 | 3~5문장 또는 불릿 | `[문제 해결 과정을 입력하세요]` |
| 5 | 결과 / 성과 | 수치 또는 정성 결과 | 2~4개 항목 | `[지표명] [00]` / `[정성적 성과를 입력하세요]` |
| 6 | 회고 | 배운 점·아쉬운 점(선택) | 1~3문장 | `[배운 점을 입력하세요]` |

### 5.4 이미지 갤러리

| 필드명 | 설명 | 반복 | 규격 | 플레이스홀더 예시 |
|--------|------|------|------|-------------------|
| 이미지 | 화면 스크린샷 등 | 0~6개 | **16:9 또는 4:3**, 한 프로젝트 안에서는 비율 통일 | `assets/placeholder-16x9.svg` |
| 캡션 | 이미지 설명 | 이미지당 0~1 | `[이 화면이 무엇인지 한 줄로]` |
| 대체텍스트(alt) | 접근성 필수 | 이미지당 1 | `[이미지 설명]` |

### 5.5 링크 / 푸터

| 필드명 | 설명 | 반복 | 플레이스홀더 예시 |
|--------|------|------|-------------------|
| 외부 링크 | 라이브 사이트 / 저장소 / 문서 등. **값 없으면 버튼 숨김** | 0~3 | "사이트 보기", "저장소 보기", "관련 문서" |
| 이전/다음 프로젝트 | 다이얼로그를 닫지 않고 옆 프로젝트로 이동 | 0~2 | "← 이전 프로젝트", "다음 프로젝트 →" |

> **개발자 참고:** 다이얼로그 열림 시 포커스를 다이얼로그 안으로 이동시키고(포커스 트랩), 닫힘 시 **원래 눌렀던 리스트 항목으로 포커스 복귀**. `role="dialog" aria-modal="true"`.

## 6. [V2] 연혁 — 타임라인

**목적:** 시간 흐름에 따른 경력·이력을 신뢰 가능한 형태로 제시한다.
**구성:** 뷰 헤더 + 세로 타임라인(스크롤) + 하단 마감. **최신이 위(내림차순)** 가 기본값.

### 6.1 연도 그룹 (선택적 상위 묶음)

| 필드명 | 설명 | 반복 | 플레이스홀더 예시 |
|--------|------|------|-------------------|
| 연도 표기 | 그룹 헤더. 스크롤 중 sticky 고정 가능 | 항목 수만큼 | `0000` |
| 연도 요약 | 그 해를 한 줄로(선택) | 0~1 | `[이 해를 한 줄로 요약]` |

### 6.2 타임라인 항목 필드 (반복 4~20개, 기본 8개)

| # | 필드명 | 설명 | 필수 | 길이/규격 | 플레이스홀더 예시 |
|---|--------|------|------|-----------|-------------------|
| 1 | 기간 | 시작–종료. 진행 중이면 종료를 "현재" | 필수 | `YYYY.MM – YYYY.MM` | `0000.00 – 0000.00` |
| 2 | 제목 | 소속 또는 사건명 | 필수 | 4~24자 | `[소속명 A]` / `[활동명 A]` |
| 3 | 부제 | 직책·역할·학위 등 | 선택 | 4~20자 | `[직책 / 역할]` |
| 4 | 유형 | 경력 / 학력 / 교육 / 수상 / 자격 / 활동 | 필수 | 택1 | `경력` |
| 5 | 설명 | 무엇을 했는지 | 선택 | 1~2문장, 40~80자 | `[담당 업무나 성과를 한두 문장으로 입력하세요]` |
| 6 | 세부 항목 | 주요 업무·성과 불릿 | 0~4개 | 각 20~40자 | `[주요 업무 항목]` |
| 7 | 태그 | 관련 기술·키워드 | 0~4개 | 2~12자 | `키워드 A` |
| 8 | 연결 프로젝트 | V1 항목 id 참조 → 클릭 시 해당 상세 다이얼로그 오픈 | 0~3 | id | `project-a` |
| 9 | 강조 여부 | 타임라인에서 시각적으로 크게 다룰 항목 | 선택 | true/false | `false` |

> **유형별 시각 구분**을 디자이너에게 요청: 경력/학력/수상 등이 한눈에 구분되어야 한다(색 또는 마커 형태). 6종 전부에 서로 다른 색을 쓰면 산만해지므로 **2~3단계 위계**로 묶을 것을 권장.

### 6.3 하단 마감

| 필드명 | 플레이스홀더 예시 |
|--------|-------------------|
| 시작점 문구 | "[여기서부터 시작했습니다]" 같은 타임라인 종점 표기 |
| 다음 뷰 유도 | "작업물 보기 →" (V1로) |

## 7. [V3] 자기소개 (About)

**목적:** 결과물 뒤의 사람 — 관점·강점·일하는 방식 — 을 전달하고 연락으로 잇는다.
**구성:** 뷰 헤더 + 본문 블록들(스크롤) + 연락 영역. **한 화면에 몰아넣지 말고 블록 단위로 등장**시킨다.

### 7.1 인사 / 프로필 블록

| # | 필드명 | 설명 | 필수 | 길이/규격 | 플레이스홀더 예시 |
|---|--------|------|------|-----------|-------------------|
| 1 | 프로필 이미지 | 사진 또는 대체 그래픽 | 선택 | **1:1**, 최소 800×800 | `assets/placeholder-1x1.svg` |
| 2 | 인사 문장 | 큰 타이포 한 문장 | 필수 | 20~40자 | `[스스로를 소개하는 한 문장을 입력하세요]` |
| 3 | 이름 + 직군 | 인트로와 동일 값 재사용 | 필수 | — | `[이름]` / `[직군]` |
| 4 | 소개 본문 | 어떤 사람인지 | 필수 | 3~5문장, 200~400자 | `[어떤 일을 해왔고 무엇에 관심이 있는지 3~5문장으로 입력하세요]` |

### 7.2 강점 / 일하는 방식 (반복 3~4개)

| 필드명 | 설명 | 반복 | 길이 기준 | 플레이스홀더 예시 |
|--------|------|------|-----------|-------------------|
| 강점 제목 | 짧은 명제 | 3~4개 | 6~16자 | `[강점 1]` |
| 강점 설명 | 근거·사례 | 강점당 1 | 1~2문장, 50~80자 | `[이 강점을 뒷받침하는 경험을 한두 문장으로 입력하세요]` |
| 아이콘/번호 | 시각 마커 | 강점당 0~1 | — | "01" |

### 7.3 기술·툴 스택 (카테고리별 묶음)

| 필드명 | 설명 | 반복 | 플레이스홀더 예시 |
|--------|------|------|-------------------|
| 카테고리명 | 스택 묶음 이름 | 2~5개 | `[카테고리 A]` (예: 주력 / 보조 / 협업 툴) |
| 스택 항목 | 배지 | 카테고리당 3~8개 | `기술 A`, `기술 B` |
| 숙련도 표기 | 사용 여부만 표기할지 단계로 표기할지 **결정 필요** | 0~1 | 기본값: **표기 없음**(막대 그래프식 % 표기는 근거 없는 수치라 권장하지 않음) |

### 7.4 부가 블록 (선택 — 콘텐츠 있을 때만 노출)

| 블록명 | 설명 | 플레이스홀더 예시 |
|--------|------|-------------------|
| 관심사 / 지향 | 앞으로 하고 싶은 일 | `[앞으로 관심 있는 방향을 입력하세요]` |
| 인용 한 줄 | 좌우명·작업 원칙 | `"[작업할 때 지키는 원칙 한 줄]"` |

### 7.5 연락 영역 (사이트 전체의 최종 CTA)

| # | 필드명 | 설명 | 필수 | 플레이스홀더 예시 |
|---|--------|------|------|-------------------|
| 1 | 유도 문구 | 연락을 권하는 한 줄 | 필수 | `[함께 이야기하고 싶다면 연락 주세요]` |
| 2 | 이메일 | `mailto:` 링크 + 복사 버튼 | 필수 | `[이메일 주소를 입력하세요]` |
| 3 | 외부 링크 | GitHub / 링크드인 / 블로그 등 | 0~4 | `링크 A`, `링크 B` |
| 4 | 이력서 파일 | PDF 다운로드(파일 없으면 항목 자체 숨김) | 0~1 | `[이력서 PDF]` |
| 5 | 응답 안내 | 회신 가능 시간대 등(선택) | 0~1 | `[연락 가능한 시간대를 입력하세요]` |

> 백엔드가 없으므로 **문의 폼은 만들지 않는다**(A4). 폼이 필요해지면 외부 폼 서비스 링크로 대체.

## 8. CTA / 내비게이션 맵

| 위치 | CTA 문구 (플레이스홀더) | 동작 |
|------|------------------------|------|
| V0 진입 메뉴 ①②③ | "포트폴리오" / "연혁" / "자기소개" | 해당 뷰로 페이드 전환 |
| V0 하단 링크 | "Email" 외 | `mailto:` / 외부 새 탭 |
| 전역 내비 (V1·V2·V3) | 3개 뷰 라벨 + 로고(→인트로) | 뷰 간 직접 전환 |
| V1 리스트 항목 | "자세히 보기 →" (호버 시 노출) | V1-D 다이얼로그 오픈 |
| V1 하단 | "연혁 보기 →" | V2로 전환 |
| V1-D 푸터 | "사이트 보기" / "저장소 보기" | 외부 새 탭 (`rel="noopener"`) |
| V1-D 푸터 | "다음 프로젝트 →" | 다이얼로그 유지한 채 내용 교체 |
| V2 하단 | "작업물 보기 →" | V1로 전환 |
| V3 연락 영역 | "이메일 보내기" (주 CTA) | `mailto:` |
| V3 연락 영역 | "이력서 내려받기" (보조) | PDF 다운로드 |

**주 CTA는 사이트 전체에서 하나 — "이메일 보내기"** 로 통일한다. 각 뷰 하단의 "다음 뷰 유도"는 보조 링크 위계로 유지해 주 CTA와 경쟁하지 않게 한다.

## 9. 콘텐츠 데이터 구조 제안 (`data.js` 단일 소스)

실제 콘텐츠 교체 시 HTML을 건드리지 않도록, 아래 형태의 객체 하나만 수정하면 되게 한다.

```js
const PORTFOLIO_DATA = {
  profile: { name: "", nameEn: "", role: "", tagline: "", email: "", links: [] },
  projects: [
    {
      id: "project-a", index: "01", title: "", summary: "",
      period: "", role: "", type: "", team: "", contribution: "",
      tags: [], category: "", thumbnail: "", accent: "",
      overview: "", problem: "", myRole: [], process: [], results: [], retrospective: "",
      gallery: [{ src: "", alt: "", caption: "" }],
      links: [{ label: "", href: "" }]
    }
  ],
  history: [
    { period: "", title: "", subtitle: "", kind: "경력",
      description: "", details: [], tags: [], projectIds: [], featured: false }
  ],
  about: {
    photo: "", greeting: "", intro: "",
    strengths: [{ title: "", body: "" }],
    stacks: [{ category: "", items: [] }],
    interests: "", quote: "",
    contact: { email: "", links: [], resume: "" }
  }
};
```

- **projects[].id ↔ history[].projectIds** 가 유일한 뷰 간 참조 관계다(연혁 항목 → 프로젝트 상세 열기).
- 빈 문자열/빈 배열인 필드는 **렌더링 자체를 생략**한다(빈 라벨이 남지 않도록).

## 10. 담당별 인계 사항

**→ portfolio-designer**
- V0은 "메뉴가 곧 화면" — 3개 진입 항목이 시각적 주인공. 작은 GNB로 축소 금지.
- 뷰 4개가 **같은 사이트라는 일관성**(타이포 스케일·여백 리듬·강조색)을 유지하되, 각 뷰는 다른 리듬을 가져야 함(V1 반복 리스트 / V2 세로 축 / V3 산문). 세 뷰 모두 같은 카드 그리드로 처리하지 말 것.
- 연혁 유형 6종(경력/학력/교육/수상/자격/활동)은 2~3단계 위계로 묶어 표현.
- 16:9(프로젝트) / 1:1(프로필) 두 가지 이미지 비율만 사용.

**→ portfolio-developer**
- 뷰 전환·다이얼로그 모두 페이드. 해시 라우팅(`#/portfolio/{id}` 포함) + 브라우저 뒤로가기 대응.
- 다이얼로그: 포커스 트랩, `Esc` 닫기, 배경 스크롤 잠금, 닫을 때 트리거 항목으로 포커스 복귀.
- 스무스 스크롤 대상은 V1 리스트 / V1-D 본문 / V2 / V3 — **다이얼로그 열림 시 배경 스크롤 인스턴스 정지** 필요(스크롤 충돌 주의).
- 콘텐츠는 `data.js`에서 렌더링. 빈 필드는 DOM 자체를 생성하지 않음.

**→ portfolio-qa**
- 딥링크 4종(`#/portfolio`, `#/portfolio/{id}`, `#/history`, `#/about`) 직접 진입 시 각 뷰가 독립적으로 완결되는지.
- 다이얼로그 닫은 뒤 리스트 스크롤 위치·포커스 복귀.
- 항목 0개 / 이미지 없음 / 링크 없음 상태에서 레이아웃 파손 없는지.

## 11. 열린 질문 (사용자 확인 필요)

1. 포트폴리오 주인의 **직군** — 필드 명칭과 강조 지점이 달라진다(A1).
2. **프로젝트 실제 개수** — 6개 미만이면 V1의 필터 칩은 제거 권장(A2).
3. 연혁 정렬 — **최신순(기본값)** vs 오래된 순.
4. 자기소개의 **숙련도 표기** — 표기 없음(기본값) vs 단계 표기.
5. **이력서 PDF** 제공 여부 — 없으면 해당 CTA 제거.
6. 인트로에서 **휠 스크롤 시 동작** — 무시 / 미세 패럴랙스 / 포트폴리오 진입 중 택1.
